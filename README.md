# AI-ассистент для чистки площадок РСЯ

Ассистент сам ходит в API Яндекс Директа и Яндекс Метрики, находит площадки,
которые сливают бюджет, и присылает отчёт. По команде — сам записывает их
в запрещённые.

Работает по расписанию на Render, участие человека не требуется.

---

## Что он делает

1. Забирает из **API Директа** статистику по площадкам сетей за 90 дней
2. Забирает из **API Метрики** поведение по тем же площадкам: визиты, отказы,
   глубина просмотра, достижения твоих целей
3. Считает средние по аккаунту и оценивает каждую площадку относительно них
4. Раскладывает площадки по четырём корзинам:
   **Запретить** / **Под наблюдением** / **Норма** / **Донор**
5. Собирает HTML-отчёт и CSV, при желании шлёт сводку в Телеграм
6. В режиме `apply` — дописывает запреты в кампании через API

---

## Логика: почему она устроена именно так

**Абсолютные пороги врут.** Совет «отключай площадки с CTR ниже 1%» бесполезен:
в РСЯ CTR 0,4% — это норма. Ассистент сравнивает площадку не с числом из статьи,
а со средним по твоему же аккаунту.

**Порог достоверности важнее самих правил.** Самая частая ошибка — отключить
площадку по трём кликам без конверсии. Три клика без конверсии — это шум,
а не приговор. Пока не набралось 100 показов и 10 кликов (или расход
в 2 целевых CPA), площадка уходит в «под наблюдением», а не в запрет.

**Одного признака мало.** Чтобы попасть в запрет, должны совпасть минимум
два независимых сигнала. Одиночный плохой показатель бывает случайностью,
совпадение двух — уже почти нет.

**Площадки с конверсиями не запрещаются вообще.** Даже если CPA высокий.
Такую площадку правильнее ограничить ставкой: запрет отрезает и те конверсии,
которые она приносила.

**Не больше 25% площадок за заход.** Массовое отключение сбивает обучение
автостратегии: кампания разом теряет часть инвентаря и уходит переобучаться.
Если кандидатов больше лимита, в запрет идут самые дорогие, остальные ждут
следующего запуска.

**Учитывается лимит Директа** — 1000 запрещённых доменов на кампанию.
Ассистент держит запас и предупреждает, когда список подходит к концу.

Все пороги лежат в `config.yaml`, менять их можно не трогая код.

## Установка: 5 шагов

### Шаг 1. Заявка на доступ к API Директа

Это единственное место, где придётся подождать. Начни с него.

1. Зайди на **oauth.yandex.ru** под своим логином Директа → создать приложение
2. Платформа — **веб-сервисы**. В Redirect URI укажи
   `https://oauth.yandex.ru/verification_code`
3. В доступах отметь **Яндекс.Директ** (полный доступ) и **Яндекс.Метрику**
   (получение статистики)
4. Сохрани — получишь `ClientID` и `Client secret`
5. В интерфейсе Директа подай **заявку на доступ к API** для этого приложения

Заявку рассматривают от часа до 3 рабочих дней, в пиковые периоды до 7.
Без одобрения токен будет возвращать ошибку 403.

### Шаг 2. Получить OAuth-токен

Открой в браузере, подставив свой ClientID:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=ТВОЙ_CLIENT_ID
```

Подтверди доступ — токен появится в адресной строке после `access_token=`.

> **Токен — это ключ от твоего рекламного аккаунта.** Не вставляй его
> в код, не коммить в git и не присылай в переписке. Единственное место,
> где он должен лежать — переменные окружения Render, которые вводишь ты сам.
> Файл `.gitignore` уже настроен так, чтобы `.env` не попал в репозиторий.

### Шаг 3. Данные Метрики

- **Номер счётчика** — виден в интерфейсе Метрики в списке счётчиков
- **ID целей** — Настройки счётчика → Цели, у каждой цели свой номер.
  Нужны те, что считаются заявкой или покупкой, а не «просмотр 3 страниц»

Метрике отдельная заявка не нужна, хватает того же токена.

### Шаг 4. Заполнить config.yaml

Обязательно задай целевой CPA:

```yaml
economics:
  target_cpa: 1500   # сколько ты готов платить за конверсию
```

Если оставить `null`, за эталон возьмётся текущий средний CPA по аккаунту.
Это работает, но учти: если текущий CPA уже плохой, ассистент будет слишком
снисходителен к мусору.

### Шаг 5. Деплой на Render

1. Залей репозиторий на GitHub
2. В Render: **New → Blueprint**, укажи этот репозиторий.
   Render прочитает `render.yaml` и создаст cron job
3. В настройках сервиса заполни переменные окружения:
   `DIRECT_TOKEN`, `METRIKA_TOKEN`, `METRIKA_COUNTER_ID`, `METRIKA_GOAL_IDS`
4. `DIRECT_CLIENT_LOGIN` заполняй **только** если у тебя агентский аккаунт
5. Запусти вручную кнопкой **Trigger Run** и посмотри логи

По умолчанию расписание — каждый понедельник в 9:00 по Москве.
Меняется строкой `schedule` в `render.yaml` (время указывается в UTC).

## Режимы

| `MODE` | Что делает |
|---|---|
| `dry-run` | Считает и отдаёт отчёт. **В Директе ничего не меняет.** Так по умолчанию. |
| `apply` | Дополнительно записывает запрещённые площадки в кампании. |

**Первые два-три запуска держи `dry-run`.** Посмотри, что ассистент предлагает
отключить, сверься со здравым смыслом, при необходимости подкрути пороги
в `config.yaml`. Переключайся на `apply` только когда согласен с его решениями.

Переключение делается в панели Render, передеплой не нужен.

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # заполни своими значениями
python src/main.py
```

Отчёт появится в папке `out/`.

Прогнать логику на синтетических данных, без обращения к API:

```bash
python tests/test_smoke.py
```

## Если что-то пошло не так

| Ошибка | Причина |
|---|---|
| `401` от Директа | Токен истёк или неверен — перевыпусти по ссылке из шага 2 |
| `403` от Директа | Заявка на доступ к API ещё не одобрена, либо агентскому аккаунту не задан `DIRECT_CLIENT_LOGIN` |
| `403` от Метрики | У токена нет прав на этот счётчик — проверь `METRIKA_COUNTER_ID` |
| Пустой отчёт | За период не было показов в сетях, либо в аккаунте нет кампаний РСЯ |
| Все площадки в «под наблюдением» | Мало статистики. Увеличь период в `config.yaml` или снизь пороги в `significance` |
| Метрика недоступна | Не критично: ассистент продолжит на данных одного Директа, точность будет ниже |

## Структура

```
config.yaml          пороги и правила — основное, что стоит править
render.yaml          расписание и переменные для Render
src/
  main.py            оркестратор
  direct_api.py      клиент API Директа: отчёты и запись запретов
  metrika_api.py     клиент API Метрики
  scoring.py         вся логика оценки площадок
  report.py          HTML и CSV
  notify.py          Телеграм
tests/test_smoke.py  прогон логики на синтетике
```

## После первого применения

Дай кампаниям **7–14 дней** на переобучение стратегии, прежде чем оценивать
результат. Сразу после массового отключения площадок метрики обычно
просаживаются — это нормальная фаза переобучения, а не провал чистки.
